# Project boundary route checks

`scripts/omp/project_boundary_routes.mjs` exports `createProjectRouteCheck(actors)`, returning `check(actor, ompSessionId, taskRoot)`. This helper is separate from boundary timing, tool gates and owner orchestration; the parent extension must explicitly integrate it before dispatch and at each boundary check.

The factory captures `DRIFT_WORKER_CONFIG` and `DRIFT_WORKER_CONFIG_SHA256`, the same variables used by the existing experimental provider. It reads the owner file with the private bounded reader, checks its digest, and calls the actual `validateWorkerConfig`. Exactly two actors must form a bijection with exactly two registered workers: `actor.model` equals `drift-experimental/` plus `identity.model_id`, and `actor.worker` and `actor.session` match the registered identity. Roles must be exactly one parent and one child; models, workers and sessions must all be distinct.

Both owner entries must explicitly declare `experimental_multi_turn: true`, `memory_mode: "linked"`, `communication_mode: "text_and_artifacts"`, and `session_binding: "fixed"`. These are existing provider keys, not new channel names. The returned function uses the production `WorkerRoutes.bind` with the actual OMP session ID and checks its resulting identity; its route object rejects a second OMP harness for a bound worker. Provider routing remains independently authoritative and unchanged.

Each check rereads the pinned owner file, revalidates command and artifact pins through the existing registration validator, requires unchanged environment bindings and verifies the passed actor against an immutable captured copy. The owner config must be outside the canonical model task root, reside in a private directory, be a private regular file without symlinks, and fit within 262,144 bytes. Any mismatch permanently fails that checker with the fixed error `PROJECT_BOUNDARY_ROUTE`; it returns no owner object, file path, command or model-visible text.

Integration at the parent extension should create one checker for its captured actor set, then invoke it with the selected actor, `context.sessionManager.getSessionId()`, and `context.cwd` before accepting a boundary. The helper does not dispatch workers, register tools, change resource limits or establish model isolation by itself. The existing restricted task tool sandbox remains necessary; its synthetic test denies `/bin/cat` access to the owner config outside the task root.

Public synthetic tests import the real TypeScript registration and routing modules through Bun, as the production extension does. They cover exact fixed-route matching, a second OMP session, actor tampering, missing or changed channel declarations, extra/missing worker routes, changed config/artifact pins, environment replacement, private-file bounds and task-sandbox denial. No models, SSH, host state or native activations are used, and this helper is not evidence of project collaboration or semantic transfer.
