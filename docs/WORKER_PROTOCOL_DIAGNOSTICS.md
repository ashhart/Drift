# Owner-only protocol failure receipts

A private input can be rejected by WorkerSession before either native backend receives it. Previously the exception handler closed the backend diagnostic writer without recording this first protocol failure, leaving an empty owner file and only the generic protocol error visible to OMP. This ticket records the failure before backend cleanup through the existing owner-only writer; no fields are added to the private worker response or activation channel.

The receipt phase is one of `protocol_admit`, `protocol_operation`, or `protocol_stream`. State is restricted to numeric sequence, accepted sequence, turns, used/budget tokens, pending-call count, ready/control-ready/active/started flags and control-update count. `protocol_op` encodes unknown=0, open=1, own_prompt=2, own_control=3, own_control_append=4, tool_result=5, stream=6, cancel=7 and close=8; `protocol_error` encodes PROTOCOL=1, LIMIT=2, CAPABILITY=3 and WORKER/other=4. Malformed sequence values become zero and no opcode supplied by an untrusted input is emitted verbatim. Stack frames retain only existing allowlisted filenames/functions and bounded line numbers; exception messages, paths, source lines, locals, model text, tool arguments and call IDs are excluded.

The original owner-path validation and exclusive 0600 writer remain in force, and the single-write lock preserves the first recorded backend failure if one already exists. A diagnostic-hook error is suppressed without replacing the original protocol error or skipping cleanup. GLM and instrumented Studio both expose the same narrow callback; runs without diagnostics continue unchanged. No new production module, serving endpoint, protocol capability or remote resource is introduced.

The development guard additionally records fixed rejection reasons and fixed tool categories, then the controller accumulates bounded-key reason/category counts. Unknown tool names map to `other`; no names, arguments, file paths or Hub bodies are copied into those counters. Existing decisions and user-visible rejection messages remain unchanged, including the current Hub behavior; the unqualified wait-policy candidate is not included.
