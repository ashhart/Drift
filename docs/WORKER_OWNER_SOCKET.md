# Owner socket beside SSH stdio

`python -m drift.serving.worker_owner_stdio` is an opt-in launcher for a retained Studio worker. It uses `launch_owner_worker` and its existing supervisor rather than launching the model directly. The ordinary SSH stdin/stdout contains only the existing own-input protocol. A separate, single-client Unix stream socket carries owner activation commands and aggregate activation receipts; there is no TCP listener or background daemon.

Required options are `--configuration FILE --configuration-sha256 HASH --activation FILE --activation-sha256 HASH --root PRIVATE_DIR --socket-name owner.sock --evidence-name termination.json --wall-seconds 60 -- command ... {worker_config}`. Both input files are pinned bounded regular JSON files. The base worker configuration must not already contain an activation FD. The separate activation JSON follows `worker_broker.ACTIVATION_FIELDS`; the launcher creates the private FD and immutable child configuration itself. Root must already exist, be owned by the current user, mode 0700, and outside Git repositories. Socket and evidence names are fresh single path components; evidence is never overwritten. Unix socket paths must fit the host's length limit, so use a short private root.

Connect one trusted owner client after launch; socket existence does not mean the model has loaded or initialized its native cache. The controller must observe the existing own-protocol readiness and intended tool-turn boundary before append or tap. Send one newline-terminated JSON object at a time and wait for its reply. Append accepts exactly `{"op":"append","path":"publication.npz","sha256":"<64 lowercase hex>","rows":12}`; tap accepts exactly `{"op":"tap","path":"own.npz","first":0,"max_rows":32}`. Paths are leaf names within the separately pinned private memory root, not arbitrary filesystem paths. Replies are the existing verified ActivationClient receipts, including sequence, session, hashes and direction. Append identifies the foreign writer and local reader; tap identifies the local writer and foreign destination. Raw arrays and text do not travel through this socket. `{"op":"abort"}` terminates the owned session without an activation success reply.

The socket is mode 0600 beneath the private root; the worker receives only its inherited activation socketpair, not the owner socket address. Filesystem permissions exclude other users, not hostile processes with the owner's UID. The qualification still needs the declared OMP/tool filesystem boundary; this launcher is not a same-user sandbox or source-ownership experiment.

Malformed, duplicate-key, oversized or pipelined frames, owner-client EOF, and activation failure abort the session. The connection remains open until own-input completion; reconnect is deliberately unsupported. Own-input EOF closes the child's input and allows bounded graceful cleanup. The owner socket thread is joined, socket removed, and supervisor cleanup receipt written only to the fresh private evidence file. Cleanup is confirmed only when both owner thread and supervised model group are gone. Missing or late supervisor evidence fails closed and retains the private generated worker configuration for diagnosis.

The independent deadline includes startup and cleanup, with a hard configured maximum of 60 seconds. Owner stdio uses the existing 262144-byte pending and 16777216-byte total relay limits; owner frames are bounded at 4,096 bytes and 1,024 requests. All callbacks and supervisor waits consume remaining time rather than adding grace after the deadline. OS-level unkillable processes or storage stalls cannot be described as a proven release; missing cleanup evidence is FAILED. No real model, linked task, transfer quality, GPU allocation release, or causal attribution is established by the synthetic regression tests.

A launcher killed by an uncatchable signal cannot finalize its own aggregate file; the inherited control pipe still closes and the independent supervisor must clean up, but release remains unconfirmed to the caller without a separately recovered supervisor receipt.
