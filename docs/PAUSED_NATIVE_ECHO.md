# Owner-released fixed echo boundary

Load `scripts/omp/paused_echo.mjs` instead of `native_echo.mjs` for the bounded two-turn plumbing qualification. It calls the existing nativeEcho through a Proxy that wraps only `drift_native_echo.execute`; the original result, tool registration and usage handlers are retained once. The installed OMP `RegisteredToolAdapter` passes ExtensionContext at execute argument 5, which this wrapper uses alongside the existing abort signal. No native probe, native echo or provider file is modified. This extension does not launch a model or authorize a larger run.

The owner supplies `DRIFT_PAUSED_ECHO_CONFIG` and `DRIFT_PAUSED_ECHO_SHA256` in the private OMP process environment. The config file lives directly in its canonical mode-0700 `root`, outside canonical `task_root`, and contains exactly `v:1`, `root`, `task_root`, `ready`, `release`, `started_at_ms`, `deadline_ms` and `model`. `model` is the full `drift-experimental/<model-id>` selector. `ready` and `release` are distinct fresh `.json` leaf names selected by the owner. Neither tool arguments nor generated text chooses paths or release behavior. The file hash is verified before its values are used; the config and control files must belong to the current UID and deny group/other access. Example values should be created by the actual owner immediately before dispatch, not copied with stale timestamps.

The absolute millisecond epoch interval cannot exceed 60,000 milliseconds; startup consumes this interval. A monotonic cap derived once at extension initialization prevents a backward wall-clock change from extending it. The current model and actual working directory must match at session start, tool entry and resume. On the first fixed echo invocation, the extension creates an exclusive ready file containing exactly `{"v":1,"phase":"tool_boundary"}` plus newline, synchronizes it and waits for the bounded owner release. The ready file contains no text, token IDs, activations, tool arguments or private identifiers.

The owner atomically publishes a mode-0600 or mode-0400 regular release file containing exactly `{"v":1,"action":"resume","ready_sha256":"<SHA-256 of exact ready bytes>"}`. Publish complete bytes through an owner-side temporary file and exclusive link/rename; exposing a partial file is a malformed release and fails closed. The extension rechecks the ready bytes and then invokes the original fixed echo, allowing its own tool result and second model turn to proceed. Each run needs its own private root and never-reused filenames; the fixed aggregate ready bytes are intentionally identical across runs, so freshness belongs to the owner's namespace and launch ledger.

All control reads use bounded regular-file checks with `O_NOFOLLOW|O_NONBLOCK`; ready creation additionally uses `O_EXCL`. Reused files, symlinks including dangling links, FIFOs, oversized/malformed files, extra fields, wrong hashes, wrong models/directories, aborts, expired deadlines and second calls produce the fixed error `PAUSED_ECHO_CONTROL`. Errors poison this boundary. Files remain for private aggregate evidence; the helper never deletes owner evidence or opens a broad file/tool API. The enclosing OMP/worker supervisor still owns complete process termination, allocator observations and model budgets: rejecting a parked tool is not itself proof a remote worker was released.

The private directory needs the deployment's existing OS/process isolation; mode bits alone do not exclude an unrestricted same-UID model shell. Keeping the fixed echo as the sole active tool is inherited from nativeEcho. This is a controlled tool-turn boundary, not continuous drift, provenance understanding or a benchmark result.
