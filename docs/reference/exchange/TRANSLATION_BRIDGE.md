# Bounded private translation bridge

This is owner-side plumbing for a sequential two-turn qualification, not a simultaneous Duo result or an all-knowledge exchange. `drift.serving.translation_bridge.translate_tap` translates exactly the last row of one verified Qwen own-cache tap through reverse-v3 at gain 1, then repeats that translated row 12 times. `translate_prefix` translates exactly one selected publication from the native GLM generated-prefix outbox through forward-v4 at gain 1.5. It retains `full_completion:false`, `final_tail:UNKNOWN` and `new_own_inputs:NOT_EXPORTED`; prompt rows, including new own tool results, are absent from that outbox.

## Loading the pinned recipes

Call `load_bridge_recipe(direction, manifest, expected_sha256, *, artifact_root, scratch, max_bytes)` from `drift.serving.bridge_recipe`, with direction `reverse` or `forward`. The manifest path, artifact root and mode-0700 scratch directory must be canonical absolute paths. Relative artifact paths resolve against the explicit artifact root. Each manifest and selected artifact is copied into a private mode-0400 snapshot, verified against its expected SHA-256, loaded through the existing StackedReader or explicit v4 loader, then checked again together with the original source before the reader is returned. Temporary files are removed. The original manifest digest is the returned `PinnedRecipe.sha256`; path normalization inside the temporary forward manifest does not replace that evidence identity. Returned readers are trusted owner-process objects, not a serialized authorization boundary.

`max_bytes` explicitly bounds the selected artifact total and cannot exceed 1 GiB; the manifest is independently capped at 1 MiB. These are translator artifacts, not model checkpoints. Their known sizes exceed the worker manifest verifier's default 64 MiB, so the controller must choose an explicit adequate host-side budget before loading them. This implementation's tests substitute tiny fake loaders and never load those pretrained artifacts.

## Source and output contracts

`translate_tap(recipe, path, receipt, *, session, source_worker, target_worker, seq, first, output, max_source_rows, max_source_bytes, max_output_rows, max_output_bytes)` consumes the exact existing tapped receipt: version, session, sequence, op, source/target, rows, next_first and digest. For Qwen's receiver configured with incoming GLM→Qwen, that tap receipt must identify Qwen→GLM. The expected session, sequence, first cursor and labels come from the controller's own ledger. All 24 canonical K/V arrays have shape `[rows,2,256]`; every layer is checked for finiteness and identical row counts before selecting the last row. The receipt records the absolute selected source interval, available rows, selected count 1, emitted count 12, copies, gain, source hash and recipe hash. The output contains 11 GLM arrays `[12,512]` and is capped at the snapshot bank's 1 MiB ceiling.

`translate_prefix(recipe, path, manifest_sha256, *, publication_seq, session, source_worker, target_worker, output, max_source_rows, max_source_bytes, max_output_rows, max_output_bytes, remaining)` consumes an immutable `TurnOutbox` manifest plus one publication from it. The controller supplies the expected manifest hash, native turn/session and GLM→Qwen route. The outbox must have been configured with this forward recipe manifest digest. The bridge validates the incomplete-prefix scope, aggregate row/byte counts, contiguous generated intervals starting at prompt_tokens, native publication ordering and selected file hash/bytes. The selected file has the exact 11 GLM `[rows,512]` layers. `forward_publication` computes fan-out count before dispatch, bounds it against both per-publication rows and the explicitly supplied remaining receiver budget, then validates all 24 output K/V arrays. Source and emitted counts remain separate.

Both source and destination directories must be private canonical roots; input arrays are read only from an immutable verified copy. Conservative archive-byte checks precede translation and exact archive limits follow it. Output uses a fresh basename, exclusive atomic link and mode 0400. No overwrite, activation delivery, bank update, model call, SSH operation or own-input frame is performed by these helpers. Hashes are integrity evidence for a trusted controller channel, not peer authentication by themselves. A same-UID unrestricted model shell still requires the existing OS/process isolation outside this library. The controller owns replay/version accounting, cumulative budgets and publication receipts; repeatedly calling a pure bridge helper does not advance a source cursor or authorize repeat delivery.

## Existing calls for the next qualification

Keep Qwen retained after its first bounded native tool turn; tap through the owner activation channel before its accumulated own rows exceed the 4,096-row refusal bound. Pass the verified tap to `translate_tap`, stage its output into the Spark bank root, and issue the bank's exact typed publication frame with the next version and returned hash/rows/recipe identity. The GLM session captures that bank version for its next reconstructed tool turn; require both rank receipts. Collect a nonempty exported GLM prefix, pass its pinned manifest to `translate_prefix`, stage the output into Qwen's activation root, append with its returned hash/emitted rows, then resume Qwen's own tool result. Owner-only transport and cleanup remain outside this bridge.

A whole Qwen prefix will not fit the current reverse bank when copied 12 times; the last-one-row policy is an explicit plumbing subset. A short GLM turn may export no generated rows, which blocks this round rather than authorizing extra inference or a fabricated final flush. This bridge neither closes that final-tail gap nor establishes source understanding, answer causality or long-context quality.
