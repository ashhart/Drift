# Owner-only local activation launch

`launch_owner_worker` in `drift.serving.worker_broker` is an opt-in local launch helper, not an OMP tool or a model-facing endpoint. It creates an AF_UNIX socketpair, assigns the actual worker FD in a generated mode-0400 worker configuration under a fresh private directory, and passes only that endpoint through the existing supervisor. The owner retains an `ActivationClient`; ordinary worker input/output remain separate stdio pipes. No activation option means no socket, no activation configuration and the existing no-link behavior.

The caller supplies a concrete trusted worker command with exactly one `{worker_config}` argument placeholder, the pinned owner worker configuration, a canonical mode-0700 root, and explicit wall/cleanup limits. Activation configuration is separate and must contain exactly session, source_worker, target_worker, memory_root, max_bytes, max_rows and max_total_rows; callers cannot inject an FD or an existing activation stanza, and target_worker must equal the worker identity. Source configuration is copied before mutation. The generated file hash is returned as config_sha256 for owner evidence; this is an ephemeral launch configuration, not a replacement for model/translator artifact verification.

The activation client exposes only typed append(path, sha256, rows) and tap(path, first, max_rows), with a fixed bound of 1,024 requests, 4,096-byte replies, absolute launch deadline, monotonic cursors and exact source/session/sequence/hash/counter validation. Arbitrary text, unknown reply fields, Boolean sequence numbers and false aggregate counters are rejected. Transport/protocol failures close the controller endpoint; existing worker-side activation failure poisoning remains in force. The activation channel is not multiplexed into worker own-input frames.

The owner writes/reads the returned process stdin/stdout as before and calls finish() for EOF or finish(abort=True) for typed supervisor abort. Explicit prior stdin closure is supported. Cleanup waits for a reaped child and dead child process group in the existing supervisor receipt, closes the retained endpoint and owner FDs, and removes only the generated configuration directory. It fails rather than reporting release when termination evidence is missing. The supervisor retains its independent wall deadline if the owner stops responding.

This helper requires the enclosing controller's existing process/filesystem isolation: private root permissions alone do not protect same-UID files from an unrestricted model shell. It does not grant model tools access to the root, create a remote SSH channel, load a translator, connect a snapshot bank, run a model or relax native qualification. The next connection is an owner process on Studio that uses this local helper and exposes a separately authenticated bounded controller route, followed by tap/translate/publish wiring under the approved host profile.

The regression launches the actual supervisor and actual ActivationServer with a synthetic NativeGate, confirms typed append changes native fixture state only through the separate socket, and confirms an activation-shaped own-stdio command is rejected. Both EOF and abort produce child-reaped/group-dead receipts and peer EOF, and the default launch has no activation endpoint. Tests first failed because the launch helper was absent; additional red regressions caught Boolean receipt sequences, incorrect total rows and explicit-EOF cleanup attempting to flush an already closed stdin.

Activation configuration binds the incoming route: source_worker=GLM and target_worker=Qwen for a Qwen worker. Append receipts preserve that GLM→Qwen route; tap receipts reverse the labels to Qwen→GLM because the exported rows originate in Qwen's own cache. ActivationClient checks these operation-specific labels exactly and closes on swapped or forged routes. Labels remain controller evidence outside token input and do not prove model-level source understanding. The actual broker fixture exercises append followed by tap through the separate socket while activation-shaped own-input commands remain rejected.
