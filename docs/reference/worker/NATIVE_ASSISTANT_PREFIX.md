# Retained native assistant serialization

Two defects reproduced with the actual Studio tokenizer and oMLX parser blocked tool continuation without any model inference. First, native parser function.arguments is a JSON string; storing it unchanged in checkpoint semantic messages made the next template render raise TypeError, because this Qwen template requires a mapping. Second, even after explicit argument normalization, a valid tool call containing an additional internal whitespace line parsed to the same semantics but failed the exact native-prefix guard when the template regenerated canonical tool markup.

The backend now normalizes each parsed argument object once, rejecting non-object and non-finite JSON, and uses that same object for semantic history and emitted tool events. Separately, it stores the exact decoded assistant text verified against the actual generated IDs. The checkpoint renderer uses this raw assistant content without separately regenerating tool_calls markup; the stored semantic message remains intact and is checked against its frozen fingerprint before rendering. Original argument values, including intent fields, remain unchanged.

The existing `ids[:len(self.consumed)] == self.consumed` guard is unchanged. Consumed IDs and the actual stop ID remain authoritative, and neither canonical-prefix replacement nor token-splicing is used. Changing prior own input, changing parsed assistant semantics, supplying mismatched raw bytes, or changing the recorded stop boundary fails closed. Tokenization that cannot exactly reproduce the actual cached sequence remains unsupported rather than being silently accepted.

The CPU matrix uses the actual checkpoint at `/home/example/.omlx/models/Vontra/Qwen3.8-Flash-Next-MLX-4bit-MTP`, its installed tokenizer, inferred mlx_vlm parser and oMLX parse_tool_calls. Program source was passed through SSH stdin with bytecode writes disabled; no model weights, serving process or private evaluation data were used. Canonical native tool markup, internal whitespace before the closing tool tag, and an additional synthetic thinking block all preserved the exact generated-ID prefix and emitted the same argument object. The checkpoint's original empty-thinking generation prefix was present in every case.

The expanded matrix found a remaining supported-mode limit: leading or trailing whitespace around the entire assistant body is stripped by the actual template, so both variants are still rejected with CAPABILITY. These are preserved limitations, not successful continuations. The reusable probe explicitly expects those rejections, as it does semantic and prior-input tampering, and does not label them supported. A native run emitting such a variant must stop and report the continuation failure; this patch makes no general claim that every valid assistant serialization is supported.

Run the CPU matrix in the installed runtime with `python scripts/omp/native_assistant_template_probe.py --checkpoint CHECKPOINT`. Focused regression tests are `tests/test_worker_assistant_prefix.py`, `tests/test_worker_codec.py`, `tests/test_worker_studio_backend.py`, `tests/test_worker_control_flush.py` and `tests/test_worker_studio_control.py`; 30 passed in 0.04 seconds. Six initial new tests were red before implementation; actual CPU evidence was TypeError for canonical parser output, then CAPABILITY for internal whitespace after normalizing arguments alone. No energy or monetary costs were measured, and real-model continuation remains a separate gate.

Final validation used the primary existing environments with PYTHONPATH=. in the isolated checkout: full reference 603 passed and three existing skips in 35.22 seconds; next-runtime 155 passed and the existing sparse-indexer parity xfail in 7.96 seconds; full plugin 59 passed and TypeScript passed. The actual-tokenizer matrix exited zero with three supported continuations and four expected guard rejections; leading/trailing outer whitespace remains a disclosed blocker for those specific generated forms. Skipped and expected-failure architecture gates are not upgraded by this ticket.
