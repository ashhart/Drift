The command validates the live/no-link/cap requirements before creating task files, writes api.py plus public verify.py, and prints explicit environment and a shell-quoted installed-OMP invocation. The model sees only assigned read/edit/run tools; only api.py is editable through the edit tool. The fixed public verifier is hash-pinned before every run and denied writes by the task subprocess sandbox. The actual API uses BaseHTTPRequestHandler and a loopback HTTP server; tests require GET /health to return 200 JSON status ok, and an unknown path to return 404 JSON. This is a small development task, not a hidden scientific evaluation.

The verifier's owner-listed run explicitly enables loopback IP networking only. Other task commands remain network-denied by default. Process forking remains denied, runtime read roots remain explicit, user/private paths remain blocked except the task directory, and execution/output/file limits remain enforced. The controller and backend SSH process have separate authority; this task sandbox is not a claim of universal isolation. Private evidence must remain outside the task and allowed runtime roots.
