# Restricted room orchestration guard

This is a room-only qualification layer around unmodified stock Duo, not the ordinary Duo development baseline and not activation-only Drift. Parent tools are exactly `task`, `hub`, `todo`; child tools are exactly `hub`, `yield`. `installRoomGuard(api, {root, parent, child})` takes an owner-selected canonical scratch directory and distinct exact provider/model selectors. Session startup and every agent wake replace the advertised tool list and verify it; every tool call independently checks model, scratch directory, and permission before execution. The only admitted task dispatch is one `duo-peer` named `DuoPeer`, with no model, cwd, tool, isolation or other override keys; the child also fails closed if its actual selected model differs. Hub addressing is restricted to Main ↔ DuoPeer, payloads are bounded, and wait is capped at two seconds.

The red executable fixture demonstrated the original gap: parent `--tools task,hub,todo` left the stock child with `ast_edit,bash,edit,glob,grep,hub,read,write,yield`, and the child successfully read a scratch sentinel. No private file was used. With the guard, the same actual installed executable advertised only `hub,yield` to the child and executed none of the injected read/bash/edit/task calls; the second parent task was blocked, there were exactly two sessions, and scratch remained unchanged. A separate fixture leaves inherited tools advertised on purpose and verifies that the independent execution hook blocks read/bash/edit before they execute. Missing tools already prevent child task dispatch; direct hook regression also checks child task rejection.

The adversarial provider is synthetic and deliberately emits forbidden calls, without any large-model inference. The positive fixture separately runs the actual Python WorkerSession core and stock Duo successfully with the restricted tools: parent six streams, child five, one open/close each, one task, one todo, three Hub calls, no errors, 1.264 seconds. Synthetic token counters are not native costs; monetary cost and energy were not measured. The synthetic probe denies all network access and blocks private home reads through its OS sandbox. A future native room launch may allow only owner-pinned worker SSH transport while retaining this guard; it requires its own frozen selectors/configuration, absolute worker/session budgets, host authority, and supervisor cleanup checks before launch. Full project work requires separate task-only tool-process containment and matched baseline permissions.
