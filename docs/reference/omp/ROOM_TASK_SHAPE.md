## Redundant identity metadata in a batch

The next native run reported TASK_KEYS with batch shape and only the top-level keys agent/context/name/tasks. A synthetic producer reproduced this exact diagnostic on actual installed OMP; without the restriction, unchanged stock Duo opened the peer with zero errors, demonstrating that this is an accepted runtime form rather than an invented vendor API. The corrected policy admits only redundant top-level agent=duo-peer and name=DuoPeer when supplied, while still requiring the one nested item to identify that exact peer; conflicting identities and model/cwd/tools/schema/task-body overrides remain rejected at both levels. It does not infer missing nested identities or admit a second task.
