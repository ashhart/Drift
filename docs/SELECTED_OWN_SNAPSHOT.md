# Last-own-row activation snapshot

The owner activation socket accepts a new distinct operation, `{"op":"snapshot_last_own","path":"selected.npz","after":0}`. `ActivationClient.snapshot_last_own(path, after)` supplies the existing activation session, next sequence and bound route on its separate inherited socket. Existing `tap(first,max_rows)` still exports its entire remaining own prefix, retains `next_first`, and rejects a 7,001-row suffix against its 4,096-row bound.

The selected operation has a separate freshness cursor, `selected_stop`, initially zero. `after` must equal the last successful snapshot's `source_stop`; the current own-row count must strictly exceed it. Selection uses the worker's last own slot, not the last physical cache slot, so later appended foreign slots are excluded. NativeGate holds one transaction around counting, selection, the existing native `tap(first=count-1)` call, cache settlement, all-layer validation and immutable publication. The selected physical slot must map to the latest own position, outside the reserved foreign interval or span. No Studio handler, chat template, model weights, task text or own-input protocol changes.

A successful reply has exactly these fields:

```json
{"v":1,"session":"qwen-session","seq":1,"source_worker":"qwen","target_worker":"glm","op":"own_snapshot","selection":"last_own_row","scope":"own","rows":1,"after":0,"source_start":7000,"source_stop":7001,"available_own_rows":7001,"sha256":"<64 lowercase hexadecimal characters>"}
```

The interval is absolute within the session's own-row sequence, not a physical KV slot, foreign-memory index or count of rows delivered. Only `[source_start,source_stop)` is exported. `source_stop=available_own_rows` and `source_start=available_own_rows-1`; skipped earlier rows are not delivered. Available own history is mechanically bounded at 1,000,000 rows, independently of the existing publication and append budgets. The selected publication is exactly one finite row in every declared layer, within `max_bytes`, written exclusively with mode 0400 under the private memory root; the old append and tap budgets/cursors remain unchanged.

Client and bridge validate exact fields, types, expected session, sequence, direction, selection, scope, freshness interval and hash. Empty history, replay, unchanged history, wrong `after`, unexpected fields, foreign routes/scope, missing layers, nonfinite entries, oversize files and a pre-existing output fail closed. Activation errors poison the native gate; invalid replies close the client's channel. Hash verification identifies the received private file and does not itself prove semantic source ownership.

For reverse translation, call `translate_own_snapshot` from `drift.serving.translation_bridge` with the pinned reverse recipe and owner-maintained expected `session`, `source_worker`, `target_worker`, `seq`, `after`, plus a fresh output and byte/row budgets. It snapshots and checks the one-row source, applies the existing reverse-v3 gain 1 map and emits 12 copies under the existing 1 MiB GLM publication limit. Metadata preserves the absolute selected interval, `source_after`, `available_source_rows`, `transmitted_source_rows=1`, `source_selection=last_own_row`, `scope=own` and `full_completion=false`. The translator is stateless: the controller must use the expected sequence and freshness cursor rather than deriving them from an untrusted receipt.

No real model, private activation or host was accessed; this change does not qualify long-context retention, semantic memory use, source attribution or Drift project execution.
